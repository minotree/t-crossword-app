## 실행

Node.js 24 이상과 pnpm 9 이상이 필요하다. SDK 3.8.0 개발 도구의 Node 요구사항을 따른다. 저장소 루트에서 실행한다.

```powershell
pnpm --filter @t-crossword/toss dev
pnpm --filter @t-crossword/toss typecheck
pnpm --filter @t-crossword/toss lint
pnpm --filter @t-crossword/toss test
pnpm --filter @t-crossword/toss build
pnpm --filter @t-crossword/toss build:ait
```

Windows 실행 정책이 `pnpm.ps1`을 막으면 같은 명령에 `pnpm.cmd`를 사용한다. 개발 서버는 5174번 포트를 사용하며 웹 앱의 기본 포트와 분리했다. `build`는 웹 번들만, `build:ait`는 웹 번들을 새로 만든 뒤 `t-crossword.ait`까지 생성한다. 산출물은 Git에서 제외한다. `deploy`는 업로드 명령이며 별도 사용자 승인 전 실행하지 않는다.

업로드 자동화를 위한 키는 워크스페이스 콘솔 `연동 → 콘솔 API 키`에서 발급하고 사용자가 로컬 터미널에서 `pnpm.cmd --filter @t-crossword/toss exec ait token add`로 등록한다. 값은 채팅·소스·명령 인수에 넣지 않는다. 등록 후 승인된 업로드는 `pnpm.cmd --filter @t-crossword/toss exec ait deploy --location ./t-crossword.ait`로 실행한다. 이 명령은 준비된 번들만 올리므로 코드가 바뀌었다면 먼저 `build:ait`를 실행한다. 공개 검토 요청·출시는 별도 승인 단계다.

`node scripts/prepare-toss-picture-books.mjs` 또는 토스 패키지의 `prepare:books`는 `reviewStatus: approved` 작품만 골라 `content/picture-book-approval.json`의 본문/해석·이미지 승인 해시와 생성 WebP를 검증한 뒤 토스 JSON을 갱신한다. `build`도 이 과정을 실행한다. 원본 변경 후에는 변경 부분을 다시 검토하고 승인 기록·WebP를 갱신해야 한다. 파일 존재나 빌드 성공으로 검토 상태를 자동 변경하지 않는다. 목록 밖의 이미지가 남으면 삭제하지 않고 실패한다.

`build:ait`는 WebP 119장의 dist 해시와 전체 dist 100MB 상한도 검사한다. 현재 이미지는 약 28MiB다. 토스 앱에 서비스 워커·오프라인 이미지 캐시는 구현하지 않았다. `.ait` 생성과 실제 토스 기기 검증·콘솔 업로드는 구별한다.

홈과 퀴즈 진입 흐름은 PWA를 기준으로 맞췄다. 홈에는 퍼즐 그림·환영 문구·`퍼즐 퀴즈 시작하기`·`단어장 관리하기`를 제공하며 난이도/크기 선택과 `새 퍼즐`은 퀴즈 화면에 둔다. 앱 내 홈 왕복은 같은 퍼즐을 유지한다. 하단 메뉴는 아이콘과 명칭을 함께 표시한다. 화면/아이콘은 토스 앱이 소유하고 TDS와 SDK 연결은 유지한다. 상단 버튼 여백과 하단 메뉴 줄바꿈을 조정했으며 최신 간격·가로 화면은 실제 기기 재확인이 필요하다.

힌트 서버 인증·차감·완성 보상 5개·오답노트 등록과 재시도를 구현했다. 사용자 승인 후 SQL Editor로 DB를 적용했고 실제 토스 인증·잔액 조회·10→9 차감·9→14 보상과 오답노트 등록/삭제·학습 기록 보존을 확인했다. 임시 HTTPS 터널로 연결 중이며 상시 서버 전환은 남아 있다. 설정은 [API README](../toss-api/README.md)를 따른다. 서버 연결 실패를 임의 잔액으로 대체하지 않는다.

- 독립적인 React 18.3.1/Vite 앱. `@apps-in-toss/web-framework` 3.8.0, TDS Mobile/AIT 2.5.1, Emotion 11을 사용한다. 웹의 React 19와 별도로 설치한다.
- TDS Provider·Button·TextField를 적용한 홈, 난이도/크기 설정, 퀴즈, 단어장 화면.
- 공개 `@t-crossword/core` API로 퍼즐 생성·예문 정답 마스킹·어휘 데이터를 사용한다. 다른 앱의 화면·라우팅·훅·저장 코드를 가져오지 않는다.
- 힌트를 선택해 영어 정답을 입력하고 완성하면 보드·학습완료 기록을 갱신한다. 모든 문제를 맞히면 단어 복습과 다음 퍼즐 기능을 제공한다.
- 정답 창은 방향·문제 번호·뜻·보라색 동의어·예문을 중앙 정렬하고 글자별 입력 칸을 제공한다. 완성 교차 셀은 읽기 전용으로 보존한다. 자동 포커스·방향키·백스페이스 이동과 정확한 단어 완성 시 자동 제출을 지원한다. 2026-10-25부터 오답 붉은색 안내는 횟수 제한이 없으며 정답 수정·삭제 시 해당 칸의 표시만 해제한다. 글자 공개·잔액·보상은 제공하지 않는다.
- 화면 방향에 관계없이 보드 가로 너비를 확보하고 문제 목록은 `문제 전체 보기`로 보드 위에 연다. 기존 상시 위아래/좌우 배치는 제거했다.
- 가로·세로 힌트 제목과 진행 숫자는 고정하고 아래 2열 목록만 스크롤한다. 동의어는 보라색으로 표시하고 긴 문구는 줄바꿈한다. 완성 시 힌트 5개 안내는 서버가 발급한 판에서 활성화하며 서버 지급 확인 후 성공을 알린다.
- 단어장 전체·즐겨찾기·학습완료·오답노트 필터, 검색·추가 표시, 즐겨찾기 저장. 오답노트 삭제는 목록만 숨기며 단어·힌트 이력·즐겨찾기·학습완료 기록을 보존한다. 기존 저장 데이터의 새 필드는 빈 목록으로 읽는다. 완료 단어는 새 퍼즐에서 제외한다.
- 토스 환경에서는 SDK `Storage`, 독립 브라우저에서는 별도 키의 `localStorage`를 사용하는 앱 전용 저장 어댑터. 비동기 저장을 순서대로 처리하고 로딩·저장 실패·재시도를 표시한다. 손상된 저장 데이터는 빈 기록으로 덮어쓰지 않는다.
- 토스 Safe Area는 TDS AIT Provider의 CSS 변수를 사용한다. SDK 뒤로가기 이벤트는 입력 창·완료 창·내부 화면을 닫고, 홈에서는 기본 플랫폼 동작을 유지한다. 실제 동작은 토스 환경에서 확인해야 한다.

## SDK 3.x 설정

설치된 3.8.0 CLI와 설정 타입을 직접 확인해 `apps-in-toss.config.ts`의 `webBundleDir`, `webView`를 사용했다. 2.x 가이드의 `granite.config.ts`, `web.commands`, `ait dev` 설정을 사용하지 않는다. 개발 서버는 Vite로 직접 실행하며 공식 `@apps-in-toss/devtools` 플러그인을 연결한다. 브라우저 mock과 패널은 개발용이며 실제 토스 동작을 보장하지 않는다.

실제 토스 앱 실행 시 SDK 브리지가 필요하다. 설치된 SDK 3.8.0 설정 타입은 `brand.displayName`이나 `webViewProps.type`을 제공하지 않아 이전 SDK의 필드를 임의로 추가하지 않았다. 앱 이름·게임 유형은 콘솔 등록 정보를 따르며 빌드 식별자는 `appName: t-crossword`로 유지한다. 사용자가 실제 토스에서 확인한 인증·힌트·보상 범위는 위 기록을 따르며 브라우저 개발 도구의 모의 성공과 구분한다.

게임 유형에 맞춰 [공식 게임 출시 가이드](https://developers-apps-in-toss.toss.im/checklist/app-game.md)를 확인했다. 사용자 식별·기록 복원·풀스크린·종료 확인·Safe Area·기기 성능 등 출시 항목은 별도 구현/실기기 검증이 필요하며 `.ait` 생성 성공만으로 충족한 것으로 처리하지 않는다.

## 남은 기능과 검증

- 상시 HTTPS API 호스팅·요청 제한·모니터링·세션/판 보관 정책. 광고는 테스트 연동을 구현했으며 DB/API 적용·실제 기기 시험·운영 광고 전환은 남아 있다.
- 그림책 61편의 편집·카드 대조·제작 기록 검토와 토스 연결은 완료했다. 검토 범위·한계는 전체 콘텐츠 검토 보고서를 따른다. 최신 `.ait`에서의 실제 기기 가독성·페이지 이동·해석·뒤로가기 확인과 콘솔 업로드는 남아 있다.
- SDK Storage 실패·완전 종료 후 기록 유지, 네이티브 뒤로가기·키보드·가로 회전·Safe Area·작은 화면·접근성의 추가 검증. 사용자가 세로 힌트 스크롤·설정 초기화 성공을 확인했다. SDK 3.x는 구형 2.x 샌드박스 대신 실제 콘솔 테스트와 개발 도구를 구분해 사용한다.
- 프로덕션 JS는 현재 약 2.33MB(빌드 gzip 약 687kB)다. 초기 로드 분리·어휘 지연 로딩 등 최적화와 실기기 성능 확인이 남아 있다. SDK·TDS를 외부 CDN에 맡기지 않는다.
- 로컬 학습 기록을 저장한다. 사용자의 요청에 따라 이어 하기는 앱을 켜 둔 동안만 제공하고 진행 중 퍼즐의 종료·새로고침 후 복원은 구현하지 않는다. 기기·계정 간 동기화와 서비스 워커·PWA 설치 기능은 제공하지 않는다.

## 의존성·이용 범위 확인 (2026-10-18)

- SDK·개발 도구: 설치한 패키지의 Apache-2.0 라이선스 확인. TDS에는 해당 라이선스를 임의 적용하지 않는다.
- TDS는 [공식 사용 안내](https://developers-apps-in-toss.toss.im/design/components.md)에 따라 앱인토스 서비스 제공을 위한 제한된 범위에서만 사용한다. TDS 코드를 웹·모바일 앱에 공유하거나 일반 웹 서비스로 배포하지 않는다. 콘솔 등록 시 약관·최종 출시 조건을 다시 확인한다.
- React/React DOM·Emotion·Vite의 MIT 라이선스와 SDK/TDS의 React 18 peer 범위를 패키지 메타데이터에서 확인했다. 새 런타임 의존성은 토스 앱에만 선언했다. 설치 중 pnpm이 기존 모바일의 Ionic/react-router peer 연결을 바꿔 경고가 발생해, 최종 lockfile에서는 기존 앱의 모든 해석 결과를 보존하고 토스 항목만 추가했다. `protobufjs` 빌드 스크립트는 임의 승인하지 않았으며 이번 빌드는 성공했다.
- 글자 입력 조작 테스트용 `jsdom` 26.1.0을 개발 의존성으로 추가했다. npm 메타데이터의 MIT 라이선스·Node 18 이상 요구를 확인했으며 앱 런타임에 사용하지 않는다. 테스트에서만 dialog·matchMedia·SDK Safe Area 상수를 보완하며 실제 기기 확인을 대체하지 않는다. 개발 도구 플러그인은 Vite 개발 서버에서만 활성화하고 테스트·프로덕션 빌드에서는 제외한다.
- 원래 단어 콘텐츠를 재사용했으며 새로운 외부 콘텐츠·폰트·이미지는 추가하지 않았다. 원본 단어의 최종 편집·이용 권한 검토를 토스 배포 성공으로 완료 처리하지 않는다.
