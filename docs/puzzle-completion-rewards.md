# 퍼즐 완성 힌트 보상

이 문서의 UUID 생성·`auth.uid()`·신뢰 경계 설명은 웹/PWA 지갑에 적용된다. 토스는 별도 mTLS 인증·서버 발급 판과 정답 검증을 사용하며, [토스 API README](../apps/toss-api/README.md)와 [설계 기록](decisions/20261018-toss-hint-api.md)을 따른다. 사용자가 실제 토스에서 힌트 10→9 차감과 완성 보상 9→14를 확인했으며, 이 결과로 웹 RPC 검증이나 토스의 동시성 검증을 완료 처리하지 않는다.

- 한 판의 모든 단어를 맞히면 현재 Supabase 힌트 잔액에 5개를 더한다. 마지막 글자를 힌트로 완성한 경우도 포함한다.
- 앱이 새 판마다 UUID를 생성한다. 서버는 인증된 사용자와 판 ID의 조합으로 지급을 기록하고, 동일 요청의 재시도에는 추가 지급 없이 현재 잔액을 반환한다.
- 잔액 변경과 지급 기록은 한 트랜잭션에서 처리한다. 지급량은 서버에서 5개로 고정하며 사용자 ID는 `auth.uid()`에서 얻는다.
- 완료 화면에는 지급 중·성공·실패 상태와 재시도 버튼을 표시한다. 보상 확인 전에는 완료 팝업의 다음 퍼즐 버튼을 비활성화한다.
- 보상 요청 중 화면을 떠나거나 새로고침한 경우 자동 복구하는 영속 대기열은 현재 없다.

## 적용과 검증

`supabase/migrations/20261018_puzzle_completion_rewards.sql`을 대상 환경에 적용해야 한다. 운영 DB 적용은 별도 승인 대상이다. 앱 배포만으로 서버 기능이 활성화되지는 않는다.

운영 DB 적용 및 실제 Supabase 통합 검증은 미실행이다. 적용 후 서로 다른 판의 5개 지급, 같은 판의 동시·반복 요청, 비인증 거부, 힌트 사용과 동시 지급, 통신 실패 후 재시도를 확인한다.

## 신뢰 경계

현재 출제와 정답 판정은 브라우저에서 수행한다. 이 RPC는 동일 판의 중복 지급을 방지하지만, 변조된 클라이언트가 새 판 ID로 허위 완성을 요청하는 것은 검증하지 못한다. 힌트를 결제·교환 등 경제적 가치와 연결하기 전에는 서버 출제 및 정답 검증을 도입해야 한다. 광고 보상용 서버 전용 RPC의 권한은 변경하지 않는다.

함수 권한과 `SECURITY DEFINER`의 고정 `search_path`는 [Supabase 공식 함수 문서](https://supabase.com/docs/guides/database/functions)를 참고했다.
