# 모바일 비회원 인증·힌트 연결

2026-10-22 구현. **로컬 코드·빌드·회귀 검사 단계이며 운영 배포·실제 익명 가입·잔액/차감/완성 보상은 미검증**이다.

## 정책과 구조

- Supabase Auth 익명 사용자를 생성/복원한다. 이메일·암호 입력은 없다. 익명 세션을 잃으면 같은 계정으로 자동 복구할 수 없다. 재설치·앱 데이터 삭제·기기 변경 후 기록 복구와 계정 연결은 제공하지 않는다.
- 모바일 앱 전용 Auth REST 어댑터가 공개 anon 키로 signup/refresh한다. 기존 설치 `@supabase/auth-js`의 익명 signup 경로와 공식 문서를 확인했다. 새 라이브러리·의존성은 추가하지 않았다.
- 토스 인증코드·mTLS는 사용하지 않는다. `mobile-hints`의 session 경계가 Supabase `auth.getUser(jwt)`로 서버 검증하고 `is_anonymous` 사용자만 수용한다. 클라이언트가 보낸 사용자 ID를 신뢰하지 않는다.
- 서버 identity는 `mobile-anonymous:<verified UUID>`, 발급 세션 해시는 `mobile-v1:` 접두사로 토스와 분리한다. Android/iOS는 같은 모바일 앱 인증 방식을 사용하지만 계정 연결 없이 기기 간 잔액 공유를 보장하지 않는다.
- `apps/toss-api`의 공통 HTTP 처리와 `packages/data`의 기존 지갑/RPC를 재사용한다. 기존 `toss_*` 테이블 이름은 역사적 명칭이며 모바일도 네임스페이스로 격리해 사용한다. 새 DB 스키마를 추가하지 않는다. 기존 토스 핸들러 기본 동작은 유지한다.
- 최초 10개, 글자 1개당 힌트 1개, 공통 단어별 한도, 판 완성 시 현재 잔액 +5. 서버가 판 배치를 공통 엔진으로 검증하고 정답·힌트·보상·소유권을 처리한다. 보상 성공 문구는 서버 completed 응답 확인 후 표시한다.
- 판 등록 응답 유실 시 같은 퍼즐/요청 UUID, 힌트 응답 유실 시 같은 판/단어/인덱스/UUID로 재시도한다. 앱 종료 후 진행 판 복원은 없다. 이미 지급된 판 정답 재시도는 서버 멱등성을 사용한다.
- 힌트 사용 단어는 모바일 로컬 오답노트 이력으로 기록한다. 오답노트의 삭제는 `hiddenHintedWords`에 목록 숨김만 저장하고 힌트 이력·즐겨찾기·학습완료는 보존한다. 같은 단어의 힌트 응답을 다시 성공적으로 받으면 해당 숨김을 해제한다. 저장 실패 시 목록 변경 성공으로 처리하지 않으며, 로컬 이력 쓰기 실패와 서버 차감 성공을 혼동하지 않는다. 기존 숨김 필드 없는 기록은 그대로 읽는다. 실제 서버 연결·Android 조작 검증은 별도 대기다.

## 보안·저장 경계

- 모바일 인증 토큰은 WebView localStorage의 별도 namespace에 저장하고 API 로그·진행 문서에 남기지 않는다. 네이티브 보안 저장으로 개선하기 전 OS/WebView 정리·XSS·기기 접근 위험이 남는다. 현재 저장을 하드웨어 암호화 저장소로 표현하지 않는다.
- refresh 실패 시 임의로 새 익명 계정을 생성하지 않으며 저장된 세션과 사용자 ID를 보존한다. 새 익명 가입 반복에 대한 악용 방지는 별도 운영 항목이다.
- Auth 익명 사용자는 DB의 authenticated 역할을 갖는다. 기존 `user_profiles`·완성 보상 등 웹 RPC 접근 권한도 배포 전에 검토한다. 모바일 지갑 테이블은 RLS 활성화·클라이언트 접근 금지·서비스 역할 RPC만 허용하는 기존 마이그레이션을 사용한다. 실제 원격 권한은 이번 작업에서 새로 조회하지 않았다.
- `mobile-hints.verify_jwt=false`는 Supabase 게이트웨이 대신 session 경계에서 JWT를 확인하고 이후 발급 세션을 검증하기 위한 것이다. 업무 요청 인증을 생략하는 설정이 아니다.
- CORS는 정확한 모바일 Origin만 등록하며 인증을 대신하지 않는다. 광고 보상 테스트는 기본 비활성 상태로 유지한다.
- 익명 가입 rate limit/CAPTCHA, 계정 정리·사용량·한도는 공개 출시 전 별도 점검한다. CAPTCHA 필수 설정을 사용하는 환경이면 현재 signup 어댑터에 챌린지 토큰 전달 UI를 추가해야 한다. 익명 기능 활성화만으로 악용 방지가 완료되는 것은 아니다.

## 승인 후 적용 순서

1. 대상 Supabase의 익명 인증 활성 상태·기존 정책·사용량을 확인한다. 비활성이라면 설정 변경 전 사용자 승인을 받는다.
2. 실제 모바일 Origin을 확인해 `MOBILE_ALLOWED_ORIGINS`를 설정한다. Android 기본 `https://localhost`는 후보이며 실제 WebView/설정과 대조한다. 기존 `TOSS_ALLOWED_ORIGINS`·토스 인증서·키는 변경하지 않는다.
3. 저장소 루트에서 `pnpm.cmd --filter @t-crossword/toss-api build:mobile-edge` 후, 승인받은 프로젝트에 `supabase functions deploy mobile-hints --project-ref <ref> --use-api`를 실행한다. 기존 `toss-hints`를 교체 배포하지 않는다.
4. 모바일 `.env.local`에 `.env.example`의 공개 URL·anon 키·mobile-hints URL을 설정한다. 서비스 역할 키·개인 토큰은 넣지 않는다. 기존 웹 키를 모바일 필수 설정으로 무조건 복사하지 않는다.
5. 모바일 build·Android sync 후 에뮬레이터에서 가입/복원·최초 10개·힌트 1개 차감·완성 +5·재시도 중복 방지·재실행 잔액을 확인한다. 테스트가 사용자를 생성하고 잔액을 변경한다는 점을 구분한다.
6. 익명 계정/세션 상실 시 처리, 만료·네트워크 실패·복원 실패, 실제 기기 보안 저장·인앱 키보드/힌트 포커스를 점검한다.

프런트 설정이 없으면 로컬 퀴즈는 유지하며 잔액/힌트는 ‘연결 필요’로 표시한다. 실제 지급하지 않은 잔액을 화면에 만들어 표시하지 않는다.

## 로컬 검사

- 모바일 인증 테스트: 최초 가입 동시 요청 합치기, 저장 복원, refresh 실패·다른 사용자 응답 거부·손상 기록 보존.
- API 테스트: 서버 검증 익명 사용자만 허용, identity/세션 네임스페이스 분리, 기존 지갑/보상/멱등성 회귀.
- API 테스트 전체에는 기존 선택적 프로파일링 검사 1개가 skip된다. 로컬 PGlite·mock 검사는 실제 Supabase 가입·기기 통합 검증을 대체하지 않는다.

공식 근거: [Supabase Anonymous Sign-Ins](https://supabase.com/docs/guides/auth/auth-anonymous), 2026-10-22 확인. 익명 사용자와 공개 anon 키의 의미를 구분한다.
