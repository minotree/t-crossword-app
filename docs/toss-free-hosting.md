## 결정과 현재 상태 (2026-10-19)

최신 상태: 사용자가 실제 토스 화면의 `Supabase 무료 인증 연결 성공`을 제공해 인증 전용 probe의 유효 코드 교환을 확인했다. 이어 `toss-hints` 전체 API v1을 기존 프로젝트에 배포했다. 최신 `.ait`는 `https://zduyaejdjwfhsiazcmrn.supabase.co/functions/v1/toss-hints`로 직접 연결하며 임시 시험 버튼은 비활성화했다. 이 번들은 PC·터널을 호출하지 않는다. 실제 기기의 잔액·출제·차감·보상 확인은 대기다. 아래 초기 미확정 상태는 검토 과정의 기록이다.

## 전체 API 빌드·배포

원본은 `apps/toss-api/src/edge.ts`·`edgeAdapter.ts`와 기존 `handler.ts`다. 다른 앱 UI를 가져오지 않는다. `pnpm --filter @t-crossword/toss-api build:edge`는 기존 workspace 의존성으로 `supabase/functions/toss-hints/index.ts`를 생성한다. 생성 파일만 직접 수정하지 않는다. Node `https` 교환 대신 실제 시험을 마친 Deno mTLS를 사용한다. 비밀 값은 빌드 중 읽지 않고 함수 실행 중 Secrets에서 읽는다. `TOSS_ALLOWED_ORIGINS`에는 기존 확인된 HTTPS Origin만 등록했다. 인증서 Secrets는 앞서 승인·등록한 값을 재사용한다. Supabase URL·service role은 호스팅 기본 환경값을 사용한다.

`supabase/config.toml`의 `toss-hints.verify_jwt=false`는 토스 전용 세션 토큰을 Supabase Auth JWT로 검사하지 않기 위한 설정이다. 인증을 생략하는 의미가 아니다. `/session`은 실제 토스 mTLS 교환으로 사용자를 확인하며 이후 요청은 32바이트 세션 토큰의 해시·DB 만료·판 소유권을 검증한다. 잔액·한도·정답·보상은 기존 SQL RPC가 처리한다. 클라이언트에 service role을 전달하지 않는다. probe 함수는 계속 JWT 검증을 유지한다. 공용 호출에 의한 무료 호출량 소모 방어·요청 제한은 아직 추가 검토 대상이다.

배포 전 `pnpm.cmd --filter @t-crossword/toss-api build:edge`로 무시되는 생성 진입점 `supabase/functions/toss-hints/index.ts`를 준비한다. 생성 번들은 커밋하지 않으며 원본·빌드 설정을 관리한다. 배포 명령은 `npx.cmd --yes supabase functions deploy toss-hints --project-ref <project-ref> --use-api`다. 인증/요청 제한 설정을 검토한 뒤 사용자 승인 범위에서만 실행한다. 이 초기 전환에는 DB 변경이 없었으며 이후 판 생성 스냅샷의 신규 SQL 적용은 최신 재시도 문서를 따른다. 새 의존성·유료 서버·별도 도메인은 추가하지 않았다. 무료 플랜 여부와 실제 조직 사용량은 콘솔에서 확인해야 하며 무제한 무료를 보장하지 않는다.

검증: API 테스트 20개·Edge 빌드(약 1.83MB)·Node 빌드·전체 workspace 타입 검사·토스 lint·최신 `build:ait` 통과. 배포 API에서 health 200, preflight 204, 무인증 balance/hint/answer 401, 무효 코드 session 401, 미허용 Origin 403, 임의 토큰 balance는 실제 DB 조회 후 401을 확인했다. DB·잔액 변경은 없었다. 유효 사용자 세션·퍼즐 생성 CPU 2초 제한·힌트 차감·보상·재시도는 실제 토스의 최신 번들에서 확인해야 한다. 과거 Node 경로의 사용자 검증을 새 Edge 경로의 완료로 대체하지 않는다.

사용자 확인 순서: 최신 `apps/toss/t-crossword.ait`를 콘솔 테스트에 업로드한 뒤 앱을 완전히 닫고 다시 실행한다. 기존 힌트 13개가 유지되는지, 퍼즐이 생성되는지, 힌트 1개 차감과 완성 보상 +5를 확인한다. 새 버전에는 `무료 인증 연결 확인` 버튼이 없다. PC API와 터널을 종료해도 이 새 번들은 직접 Supabase로 연결한다. 기존 버전 테스트가 남아 있으므로 로컬 프로세스는 임의 종료하지 않았다.

사용자 기준은 **별도 서버 관리 없이 무료 범위에서 토스 출시**다. 유료 Node 호스팅과 Docker 운영 방향을 중단한다. 앞서 준비한 Docker 파일은 미배포 참고 자료로 남겨 두며 필수 단계로 안내하지 않는다. 유료 전환·서버 가입·비밀 업로드·배포·기존 파일 삭제는 실행하지 않았다.

우선 후보는 기존 Supabase의 관리형 Edge Functions다. 서버 프로세스를 직접 운영하지 않고 현재 DB의 토스 지갑 RPC를 재사용하는 방향이다. **실제 토스 mTLS 연결이 확인되지 않아 이전 가능성을 확정하지 않는다.**

## 확인한 근거와 제한

- [Deno 공식 Fetch 문서](https://docs.deno.com/api/deno/fetch/)는 `Deno.createHttpClient({ cert, key })`로 PEM 인증서·키를 전달하는 mTLS를 지원한다. 일반 Deno 지원이 Supabase 호스팅의 동작 증명은 아니다.
- [Supabase 저장소의 사용자 장애 보고 #50534](https://github.com/orgs/supabase/discussions/50534)는 2026-09의 특정 hosted runtime에서 mTLS 클라이언트 생성 시 종료 문제를 보고한다. 답변의 키 형식 변환 제안은 운영사 보장이나 검증 완료 근거가 아니다. 현재 프로젝트에서 재현 여부를 확인해야 한다. 기존 키는 임의 변환·교체하지 않는다.
- [Supabase 요금 문서](https://supabase.com/docs/guides/platform/billing-on-supabase)는 Free에 Edge Functions 월 500,000회, DB 프로젝트당 500MB, egress 5GB를 표시한다. 조직 전체 사용량도 확인해야 한다. 토스 사용자 수와 함수 호출 수는 같지 않으며 인증·잔액·판 생성·힌트·정답 요청마다 호출을 사용한다. 현재 계정 요금제·사용량은 조회하지 않았다.
- [실행 제한](https://supabase.com/docs/guides/functions/limits)은 메모리 256MB·요청당 CPU 2초 등을 명시한다. 기존 Node 서버 퍼즐 생성의 실제 Edge CPU 시간·번들 크기를 별도 측정해야 한다. mTLS 성공만으로 전체 API 이전을 완료 처리하지 않는다.
- 토스 교환 URL과 요청/응답 형식은 기존 Node 구현 및 2026-10-18 공식 문서 확인 기록을 따른다. 이번에는 토스 공식 페이지 본문을 다시 읽지 못했다. 런타임 시험 전 변경 여부를 재확인한다.

## 준비한 최소 시험

`supabase/functions/toss-mtls-probe/index.ts`는 토스 인증 코드 교환만 시험한다. DB 접근·사용자 지갑 생성·잔액 변경 없이 성공 여부와 제한된 HTTP 상태만 반환한다. 원문·사용자 식별키·인증서·키는 반환하거나 로그에 쓰지 않는다. 이 함수는 앱에서 사용할 정식 API가 아니다.

게이트웨이 JWT 검증은 유지하고 별도의 32자 이상 무작위 `TOSS_PROBE_TOKEN`을 `X-Probe-Token` 헤더로 요구한다. 함수 Secrets에는 `TOSS_MTLS_CERT_PEM`, `TOSS_MTLS_KEY_PEM`이 필요하다. 기존 파일 경로 대신 PEM 내용을 서버 측 비밀 저장소에 등록해야 하므로 사용자 승인 후 진행한다. 내용을 채팅·소스·명령 인수·브라우저 번들에 넣지 않는다. 유효한 PKCS#8 비암호화 PEM만 시험 코드가 받으며 다른 형식은 변환 전에 별도로 검토한다.

실제 시험 순서:

1. 프로젝트가 Free인지와 현재 DB·전송·함수 사용량을 확인한다. 유료 전환을 선택하지 않는다.
2. 배포 승인 후 probe Secrets를 안전하게 등록하고 임시 함수만 배포한다. DB 마이그레이션은 필요 없다. JWT 검증을 끄지 않는다.
3. 실제 토스가 발급한 새로운 일회용 코드로 한 번 교환한다. 사용한 코드는 재사용할 수 없고 브라우저 mock 코드는 검증에 쓸 수 없다.
4. `authenticated: true`일 때만 이 프로젝트의 mTLS 호환성이 확인된 것으로 기록한다. 4xx/5xx 수신만으로 클라이언트 인증 성공을 단정하지 않는다.
5. 성공하면 기존 DTO·데이터 접근·핸들러를 앱 간 import 없이 재사용할 수 있게 준비하고, Edge용 진입점·경로·인증 경계를 구현한다. 퍼즐 CPU/번들·보안·재시도를 검사한 뒤 앱 주소를 전환한다. 실패하면 무료 조건 내 대안을 검토하며 유료 서버로 자동 전환하지 않는다.

## 검증 상태

### 실제 토스에서 누르는 시험 버튼

시험 빌드에서만 `VITE_TOSS_AUTH_PROBE=true`로 설정 메뉴의 `무료 인증 연결 확인`을 표시한다. 버튼은 SDK로 새 코드를 발급하고 로컬 API의 `/auth-probe`를 통해 위 Supabase 함수로 전달한다. probe 토큰과 service-role 키는 로컬 API에만 있으며 `.ait`에 넣지 않는다. 서버의 `TOSS_AUTH_PROBE_SETTINGS_PATH`는 무시되는 probe 토큰 파일을 가리킨다. 설정이 없으면 시험 경로는 404다. Origin이 없거나 허용 목록에 없으면 거부하며 DB 접근은 하지 않는다. 이 로컬 중계는 호환성 시험용이고 최종 운영 구성이 아니다.

사용자 확인 순서: 최신 `apps/toss/t-crossword.ait`를 콘솔 테스트에 올린 뒤 실제 토스에서 `설정 → 무료 인증 연결 확인`을 누른다. `Supabase 무료 인증 연결 성공`이 보이면 실제 코드 교환 성공으로 기록한다. 실패 메시지만으로 원인을 단정하지 않는다. 시험 동안 PC API와 임시 터널이 실행 중이어야 한다. 임시 주소는 재시작하면 바뀔 수 있다. 현재 번들은 이 시험용 주소를 포함하므로 정식 출시 대상으로 쓰지 않는다. 시험 종료 후 앱의 `VITE_TOSS_AUTH_PROBE`와 API의 `TOSS_AUTH_PROBE_SETTINGS_PATH` 설정을 해제해 다시 빌드한다.

사용자 승인과 CLI 로그인 후 기존 crossword 프로젝트에 Supabase CLI 2.121.0의 `--use-api`로 `toss-mtls-probe` v1을 배포했다. 함수는 ACTIVE이며 `verify_jwt: true`를 확인했다. 인증서·키·probe 토큰 3개를 프로젝트 Secrets에 등록했다. 기존 인증서와 키의 일치·현재 유효·PKCS#8 형식을 비밀 출력 없이 확인했다. 등록용 로컬 파일은 Git 무시 대상이며 등록 후 중복 인증서·키 내용을 제거하고 probe 토큰만 남겼다. 원본 인증서 파일은 변경하지 않았다.

원격 검사: probe 토큰 없는 요청은 HTTP 401, 토큰과 무효 인증 코드 요청은 함수 HTTP 502 / `reachedUpstream: true`, `upstreamStatus: 200`, `authenticated: false`를 반환했다. 이 프로젝트에서 mTLS 클라이언트 생성과 토스 API 응답 수신까지 확인했다. **무효 코드의 HTTP 200은 실제 사용자 인증 성공을 증명하지 않는다.** 실제 토스가 새로 발급한 일회용 코드로 `authenticated: true`를 확인해야 한다.

원격 번들·기동은 성공했지만 Deno 전용 타입 검사·로컬 런타임 검사·실제 유효 코드 교환·계정 요금제/사용량 확인·전체 API 이전은 미실행이다. DB·지갑·기존 앱 API 주소와 Node 서버 동작은 변경하지 않았다. 유료 전환·결제·커밋·푸시를 하지 않았다.

## 요청 제한의 적용 범위 (2026-10-19)

공통 API 핸들러에 인스턴스별 메모리 카운터를 추가했다. 전체 POST 600회/60초, 인증 교환 합계 20회/60초, 세션 해시별 전체 120회/60초와 판 생성 6회·힌트 30회·잔액/정답 각각 90회/60초를 적용한다. 초과 시 외부 호출 전에 429와 대기 시간을 반환하며 본문도 실제 수신 65,536바이트까지로 제한한다. 상세 경계·공유 한도는 [API README](../apps/toss-api/README.md#인스턴스별-요청-제한-2026-10-19)에 기록했다. 추가 의존성·서비스·요금제·DB 변경은 없다. 원격 배포는 미실행이다.

2026-10-19 확인한 [Supabase 호출량 공식 문서](https://supabase.com/docs/guides/platform/manage-your-usage/edge-function-invocations)는 응답 상태와 관계없이 함수 호출을 집계하고 OPTIONS는 제외한다고 설명한다. 따라서 함수 내부의 429는 이미 발생한 호출을 무료 한도에서 제외하지 못한다. 이 제한으로 줄이는 것은 후속 mTLS·DB·퍼즐 생성 작업이다. CORS도 직접 HTTP 호출의 인증 수단이 아니다.

카운터는 worker 재시작 시 초기화되고 worker 간 공유되지 않는다. 월 호출량 소모 방어와 다중 worker 전체의 강제 제한은 **미완료**다. 이를 해결하려면 신뢰할 수 있는 함수 진입 전 차단과 직접 주소 우회 방지 구성을 별도로 검증해야 한다. 현재 토스 자체 세션 대신 Supabase JWT 검증을 단순히 켜면 기존 인증 흐름이 깨진다. 별도 유료 프록시나 Redis를 기본 전제로 추가하지 않았다. Usage 확인·이상 증가 대응, 실제 Edge 부하/CPU·동시성·응답 유실 검증은 남은 작업이다.
