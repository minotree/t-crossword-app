# Vercel 웹/PWA 배포

작업·승인 기준은 [AGENTS.md](../AGENTS.md)를 따른다. 빌드 성공과 실제 배포·기기 검증은 구분하며 배포에는 사용자 승인이 필요하다.

## 프로젝트 설정

- 저장소 루트에서 배포한다. Root Directory는 `.`이며 `apps/web`로 바꾸지 않는다.
- Framework Preset: Vite
- Install Command: `pnpm install --frozen-lockfile`
- Build Command: `pnpm --filter @t-crossword/web build`
- Output Directory: `apps/web/dist`
- 라우트 새로고침 및 서비스 워커 캐시 정책은 루트 `vercel.json`에 정의되어 있다.

Vercel Environment Variables에 다음 공개 클라이언트 환경 변수를 설정한다.

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

`.env.local` 파일을 업로드하지 않는다. Supabase service-role 키는 웹 빌드에 넣지 않는다.
Supabase 프로젝트의 익명 로그인 활성화와 기존 마이그레이션 적용·RLS 검증은 별도 준비가 필요하다.

## 동작 범위

- HTTPS에서 manifest와 192/512px PNG 아이콘으로 설치 정보를 제공한다.
- 빌드 마지막 단계가 파일 해시별 서비스 워커를 생성해 HTML·JS·CSS·아이콘·내장 단어장을 캐시한다.
- 홈 이외의 화면은 경로별로 코드를 나눠 불러온다. 첫 화면 로딩 뒤 브라우저 유휴 시간(대기 한도 3초, 미지원 브라우저는 1초 타이머)에 서비스 워커를 등록한다. 오프라인 메뉴 이동을 위해 분리된 JS도 설치 캐시에 포함하므로, 초기 실행 JS는 줄지만 설치 준비 중 백그라운드 다운로드의 총량까지 줄어드는 것은 아니다.
- 첫 방문과 캐시 설치 완료에는 인터넷이 필요하다. 이후 오프라인에서 로컬 퍼즐·단어장·즐겨찾기·학습 기록을 이용할 수 있다.
- Supabase API 응답·토큰은 서비스 워커에 캐시하지 않는다. 힌트 조회·차감·신규 인증은 온라인 기능이다.
- 그림책은 초급 45편, 중급 9편(시·에세이·소설 각 3편, 총 36장), 성인용 고급 7편(시 2편·에세이 2편·소설 3편, 총 38장)을 제공한다. 중급 소설은 SF·무협·환생, 고급 소설은 SF·현실 미스터리·법정 드라마 장르를 표시한다. 고급 에세이는 각 3장, 소설은 각 10장이다. 여러 장의 작품은 이전·다음 버튼과 페이지별 한글 해석을 제공한다. 그림책 이미지는 설치 시 일괄 캐시하지 않고, 성공적으로 내려받은 이미지부터 캐시한다. 처음 여는 이미지와 캐시에서 삭제된 이미지는 인터넷이 필요하다.
- 그림책 원본을 변경하면 저장소 루트에서 `python scripts/prepare-picture-books.py`로 웹용 WebP와 목록을 갱신한다(Python/Pillow 필요). 생성된 `apps/web/public/picture-books/`와 `apps/web/src/data/`의 그림책 JSON을 배포 소스에 포함한다. Vercel 빌드에는 Python이 필요하지 않다.
- 업데이트는 안내 버튼을 눌렀을 때 적용한다. 현재 퍼즐은 다시 생성되며 기기에 저장한 학습 기록은 유지한다.
- 기기 저장은 배포 주소(origin)별로 분리된다. localhost 또는 Preview 주소의 학습 기록은 Production 주소로 자동 이전되지 않는다.
- 브라우저별 설치 메뉴가 다르다. iOS는 Safari 공유 메뉴의 '홈 화면에 추가'를 이용한다.

## 배포 후 필수 검증

배포 전에는 그림책 원본·해석·이미지·제작 기록·웹용 파일의 대응을 확인한다. `draft-unreviewed` 상태의 최종 편집·권리 검토와 필수 표시 사항도 확인하며, 빌드 성공으로 권리 검토를 완료 처리하지 않는다. 난이도별 제작 절차는 `content/*/README.md`와 `AGENTS.md` 14~15절을 따른다.

1. 홈·퀴즈·단어장·그림책·설정 직접 접근 및 새로고침. 그림책 난이도 전환, 초급·중급·고급 작품 열기, 페이지 이동·한글 해석·목록 복귀·브라우저 뒤로 가기 확인. 고급 에세이 3장과 소설 세 장르 각각 10장의 첫·끝 페이지, 잘못된 페이지 번호의 첫 장 복귀도 확인한다.
2. manifest와 아이콘 HTTP 응답, 설치 후 독립 창 실행.
3. 정답 기록 후 종료·재실행, 재출제 제외 및 설정에서 초기화.
4. 서비스 워커 설치 완료 후 오프라인 재실행과 모든 로컬 화면 이동.
5. 오프라인에서 힌트 차감 방지, 연결 복구 후 인증·잔액 조회.
6. 새 버전 배포 시 업데이트 안내·명시적 적용 및 학습 기록 유지.
7. 그림책 이미지 열기 후 오프라인에서 재열기, 열지 않은 이미지의 로딩 실패 안내, 온라인 복구 후 다시 열기 확인.
8. 첫 홈 화면 뒤 각 메뉴의 로딩·실패 안내, 직접 주소 진입, 캐시 설치 완료 후 오프라인 메뉴 전환, 새 버전 적용 뒤 분리된 JS 로딩을 확인한다.

실제 배포 및 기기 검증은 아직 수행하지 않았다.

현재 브라우저·기기 확인은 사용자가 맡기로 했다. 코드·콘텐츠 자동 검사와 사용자 기기 확인 결과는 [progress.md](../progress.md)에 별도로 기록한다. 렌더링 테스트 통과만으로 설치·오프라인·터치·실기기 가독성이 검증되었다고 판단하지 않는다.

## 번들 분리 검사

`vite build`는 `.vite/manifest.json`을 생성한다. 저장소 루트에서 웹 빌드 후 `node --test apps/web/scripts/check-build.mjs`를 실행하면 홈의 정적 의존성에 기능 화면·단어 데이터가 포함되지 않는지, 네 메뉴와 공통 단어 데이터가 설치 캐시에 포함되는지, 생성된 서비스 워커가 캐시된 메뉴 JS를 오프라인으로 반환하는지 검사한다. 실제 기기에서의 캐시 설치·업데이트 검증을 대체하지 않는다.
