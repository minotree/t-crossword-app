# 공통 엔진의 기기 출제와 서버 판 등록

상태: 로컬 구현·자동 검사 완료. 2026-10-20 사용자 진행 승인 후 `toss-hints` v3 ACTIVE 배포·새 토스 테스트 번들 업로드 완료. 실기기 검증·공개 검토 요청·출시는 미실행.

후속 Origin 점검(2026-10-20): 현재 테스트 주소의 허용·사전 요청과 미허용 주소의 403을 확인했다. 아래 배포 직후 시간 초과는 재현되지 않았지만 원인 확정은 아니다. [실측·원격 동시성 시험 계획](../toss-remote-verification.md)과 [무료 운영 대응](../toss-free-operations.md)을 우선한다.

## 결정

웹/PWA·토스·향후 Ionic/Capacitor 앱은 `packages/core`의 동일한 출제 엔진을 각 기기에서 실행한다. UI·Worker·플랫폼 인증·저장은 앱이 소유하고, 출제·학습완료 제외·배치 검증·힌트 한도는 core에서 공유한다. 모바일은 아직 준비 화면이며 퍼즐 화면을 구현한 상태는 아니다.

웹은 기존 기기 출제를 유지하면서 `vocabularyForProgress`를 재사용한다. 토스는 `generateDevicePuzzle`이 module Web Worker에서 공통 엔진을 실행한다. Worker가 없는 환경은 같은 엔진으로 직접 실행하며, Worker 오류·메시지 오류·30초 초과는 실패 안내와 수동 재시도를 제공한다. 지원되는 Worker의 실패를 서버 출제로 자동 우회하지 않는다. Worker 번들에 어휘가 포함되어 토스 dist가 약 1.07MB 증가한다. 실제 Toss WebView의 Worker 실행과 고급 12×12 체감 속도는 별도 검증한다.

## 서버 신뢰 경계

새 앱은 `POST /round/register`에 난이도·크기·학습완료 ID·요청 UUID·단어 ID/시작 행/열/방향의 배치 배열만 보낸다. 서버는 공통 단어장으로 정답·뜻·예문·힌트 한도·번호·그리드를 재구성한다. 클라이언트의 정답·힌트 한도·완료 주장으로 지갑을 갱신하지 않는다.

`registerCrosswordDraft`는 생성 엔진과 같은 후보 선택·교차 배치·번호 부여 함수를 사용한다. 미등록/난이도 초과/학습완료/중복 단어, 범위 초과, 겹침·글자 불일치·단어 앞뒤 접촉·옆면 접촉, 연결되지 않은 단어를 거부한다. 빈 판은 출제 가능한 후보가 없을 때만 허용한다. 요청 본문 바이트 상한·세션 확인·서버 전용 RPC/RLS·힌트 차감·최종 정답 확인·보상 1회 지급은 유지한다.

학습완료 ID는 클라이언트 학습 선호이며 서버의 학습 성취 증명이 아니다. 유효한 배치가 생성 엔진의 최다 단어 결과인지 또는 사람이 실제로 풀었는지를 증명하지 않는다. 작은 유효 판의 반복 제출·자동 풀이·봇 방지를 보장하지 않는다. 이런 남용을 제한하려면 별도 보상 정책이 필요하며 이번 변경에서 추가하지 않는다.

## 재시도와 호환성

- 토스 gateway는 같은 설정의 생성 결과 Promise·배치·요청 UUID를 보관한다. 통신 실패·401 재인증·429 이후에는 다시 출제하지 않고 같은 내용을 재등록한다. 성공하면 다음 판은 새 UUID와 새 기기 출제를 사용한다. 기기 출제 자체가 실패하거나 서버가 만료·불일치·유효하지 않은 배치를 명시적으로 거부하면 다음 수동 시도에서 다시 생성한다.
- 서버 fingerprint에 `device-v1`과 정규화한 배치를 포함한다. 같은 UUID로 다른 배치를 보내면 기존 SQL이 불일치를 거부한다. 저장 스냅샷을 반환하므로 응답 유실 뒤 중복 판·보상 생성 방지를 유지한다.
- 기존 `POST /round`는 이미 업로드된 구버전 앱의 서버 출제 호환 경로다. 새 앱은 이 경로로 fallback하지 않는다. 두 경로는 같은 세션별 판 요청 제한을 공유한다. 구버전 경로가 남는 동안 서버 출제 CPU 검증 과제도 완전히 사라지지 않는다.
- 새 등록에도 HTTP 호출·DB 저장·전송은 필요하다. 서버 계산량은 줄지만 함수 호출 수가 사라지거나 월 무료 호출량 소모가 차단되는 변경은 아니다.
- 서버를 설정한 토스의 보상 대상 판은 등록 성공 후 퀴즈를 연다. 오프라인 보상 대상 판 등록·종료 후 진행 판 복원은 추가하지 않는다. 서버 미설정 개발 모드에서는 기기 출제만 가능하고 힌트·보상은 제공하지 않는다. 웹/PWA의 기존 오프라인 범위·보상 신뢰 경계는 그대로다.

## 적용 순서와 검증

기존 판 스냅샷 SQL을 재사용하므로 새 마이그레이션은 없다. **API 배포 → 새 `.ait` 업로드 → 실제 토스 테스트** 순서로 적용한다. 기존 API에 새 앱을 먼저 올리면 `/round/register`가 404이므로 퍼즐 시작이 실패한다. 2026-10-20 기존 crossword 프로젝트의 API v3 배포 후 30,447,979바이트 번들을 CLI로 테스트 업로드했다. deploymentId는 `01a154af-c194-7925-99c1-1293b5e9e823`이다. DB·Secrets·인증서·요금제는 변경하지 않았다.

원격 기본 경계 검사는 health 200·무인증 balance 401·무인증 등록 401·무효 배치 400(`invalid_round_draft`)·유효 배치/가짜 세션 401을 확인했다. `scripts/verify-toss-device-api.mjs`는 실제 사용자 인증이나 지갑 변경 없이 이 경계를 확인한다. 마지막 미허용 Origin 검사는 20초 시간 초과였고 해당 요청 1회 재확인도 시간 초과로 미확인 상태다. 스크립트 전체는 exit 1이며 전체 원격 검사 통과로 기록하지 않는다. 유효 사용자 판 등록·기기 Worker·차감/보상은 실제 토스에서 별도 확인해야 한다.

자동 검사는 core의 세 난이도×세 크기 왕복 재구성·위조/범위/중복/접촉 검증, API의 정답/한도 재구성·구버전 호환·공유 요청 제한, PGlite의 실제 SQL 등록 응답 폐기 후 스냅샷 재사용, 토스 gateway의 UUID/배치 재사용·Worker 실패·지원 경로를 확인한다. PGlite는 실제 다중 DB 연결 경합이나 네트워크 단절을 대체하지 않는다. 실제 토스 기기에서는 Worker 로드·고급 12×12·학습완료 제외·힌트 차감·완성 +5·실패 재시도를 확인해야 한다.
