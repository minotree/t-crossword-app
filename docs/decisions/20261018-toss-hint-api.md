# 토스 힌트 지갑 인증과 서버 경계

상태: 구현·자동 검사 및 사용자 SQL 적용·실제 토스 인증/힌트/보상 검증 완료. 상시 서버·추가 기기 검증 대기.

사용자 지정 외부 폴더의 인증서·개인 키의 파싱·일치·유효기간을 확인하고 무시되는 서버 설정에 경로를 연결했다. 내용은 출력하거나 저장소에 추가하지 않았다. 실제 토스 기기에서 mTLS 인증과 지갑 조회·차감·완성 보상이 동작했다. 로컬 API는 외부 네트워크 접근이 필요하며 임시 HTTPS 터널로 테스트 중이다.

토스 힌트는 브라우저가 전달한 사용자 식별키를 그대로 믿거나 웹의 익명 Supabase 세션과 연결하지 않는다. SDK 일회용 인증 코드를 토스의 공식 mTLS 파트너 API로 교환하고 확인된 사용자의 별도 힌트 지갑을 사용한다.

인증서 기반 HTTPS 호출과 공유 TypeScript 엔진의 서버 출제를 위해 `apps/toss-api`에 작은 Node.js 서버를 둔다. Supabase Edge 런타임에서 클라이언트 인증서 호출이 가능한지 검증되지 않은 상태로 의존하지 않는다. DB 저장과 차감·보상은 Supabase SQL/RPC, 데이터 접근은 `packages/data`, 재사용 DTO와 검증은 `packages/contracts`, 퍼즐과 단어 규칙은 `packages/core`가 담당한다. 화면과 SDK 호출은 토스 앱이 소유한다.

클라이언트는 서버가 발급한 판 ID로 힌트·정답을 요청한다. 서버가 정답과 단어별 힌트 한도를 저장하고 잔액을 잠금 처리하므로 다른 사용자의 판 사용, 한도 초과, 요청 재전송에 따른 중복 차감, 단순 완료 주장에 따른 중복 보상을 거부할 수 있다. 자동 정답 획득·봇 탐지까지 보장하지는 않는다.

기존 웹 지갑·인증·완성 보상 RPC는 이번 변경에서 바꾸지 않는다. 토스 지갑의 적용 절차·권한·잔여 검증은 [토스 API README](../../apps/toss-api/README.md)를 따른다. 운영 DB 적용·서버 배포는 별도 사용자 승인을 받은 뒤 실행한다.
